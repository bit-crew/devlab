# Data Engineering Rules Manifest

## PySpark Best Practices
1. **API Exclusivity**: Always use the PySpark DataFrame API. Strictly avoid RDDs and UDFs unless explicitly unavoidable (and document why if used).
2. **Joins**: Optimize joins by using `broadcast` for small dimension tables to avoid shuffles and reduce memory overhead.
3. **Memory Management**: Handle partitions efficiently to prevent OOM errors on AWS EMR/Glue. Repartition or coalesce when appropriate before writes or after severe filtering.
4. **Data Formats**: Output data must use columnar formats like Parquet or Iceberg unless specified otherwise, optimizing for read performance.
5. **Schema**: Always enforce schemas strictly using `StructType` instead of inferring them to reduce overhead, avoid unintended casts, and catch errors early.

## Code Quality & Documentation
1. **Documentation**: Use Google Style Docstrings for all functions and classes. Explain the why, not just the what.
2. **Type Hinting**: Use strict Python type hints for all parameters and return types.
3. **Modularity**: Code should be modular, testable, and follow a minimalist, functional, and Anti-SOLID design. Avoid factories, single-use interfaces, or unnecessary abstraction layers.
4. **Idempotency**: All data pipelines must be idempotent. Re-running a pipeline should safely overwrite or append without duplicating data.

## AWS Integration
1. **S3 Paths**: Ensure all paths follow standard S3 URI formats (`s3://...`). Use explicit partition path structuring.
2. **Credentials**: Never hardcode AWS credentials; use IAM roles, Boto3 default credential chains, or environment variables.
